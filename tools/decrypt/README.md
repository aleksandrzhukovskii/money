# money-decrypt

Reads Money Tracker backups on a machine you control: decrypts one to plain
SQLite, or re-encrypts one for a new app build.

The app deliberately has no "Export Plain" button. An unencrypted copy of your
finances shouldn't land in a browser download folder that syncs to a cloud drive —
so the plaintext export lives here instead, where you decide where the file goes.

## Build

```sh
cd tools/decrypt
go build -o money-decrypt .
```

Requires Go 1.25+ (for the standard library's `crypto/pbkdf2`, and
`golang.org/x/term` — the one dependency, used to turn off terminal echo at the
password prompt).

## Use

The password is read from `$MONEY_PASSWORD`. Without it you're prompted, and
nothing is echoed as you type; piped stdin still works for scripts.

```sh
# Decrypt a backup exported from Settings -> Export Encrypted
MONEY_PASSWORD='...' ./money-decrypt money-tracker-2026-09-05.enc
# -> money-tracker-2026-09-05.db

# Or let it prompt — the password stays out of your history, environment and screen
./money-decrypt -out finances.db money-tracker.enc

# Inspect it
sqlite3 finances.db 'SELECT type, date, amount, comment FROM transactions LIMIT 10;'
```

You can decrypt the file the app syncs to GitHub the same way — download
`money-tracker.enc` from the private repo and point the tool at it.

To recover the GitHub token if you still know the password, copy the
`money-tracker-credentials` value out of the browser's localStorage into a file
and pass `-base64`; it decrypts to JSON:

```sh
MONEY_PASSWORD='...' ./money-decrypt -base64 credentials.txt
```

### Flags

| Flag | Meaning |
|---|---|
| `-out` | Output path, `-` for stdout. Defaults to the input with a `.db` extension. Required with `-convert`. |
| `-convert` | Re-encrypt with the app's current parameters instead of decrypting. |
| `-migrate` | Do the whole round trip against the repo: fetch, back up, re-encrypt, verify, upload. |
| `-repo` | `owner/repo` to migrate (with `-migrate`). |
| `-token-file` | Read the GitHub token from a file instead of `$GITHUB_TOKEN`. |
| `-remote-path` | Path of the encrypted file in the repo (default `money-tracker.enc`). |
| `-backup-dir` | Where `-migrate` saves the original before uploading (default `.`). |
| `-dry-run` | With `-migrate`, do everything except the upload. |
| `-f` | Overwrite the output file; with `-migrate`, re-encrypt even if already current. |
| `-iter` | Only try this PBKDF2 iteration count instead of every known one. |
| `-base64` | Treat the input as base64 — for the localStorage credentials blob. |

## Migrating

The app deliberately carries no version header and understands exactly one
parameter set, so changing it makes existing files unreadable to the app. This
tool is the bridge.

`-migrate` does the whole thing — fetch, back up, re-encrypt, verify, upload:

```sh
export GITHUB_TOKEN='ghp_...'      # or use -token-file
export MONEY_PASSWORD='...'

./money-decrypt -migrate -repo me/money-data -dry-run   # look first
./money-decrypt -migrate -repo me/money-data            # then do it
```

The token needs write access to that repo. Order of operations is deliberate:

1. Fetch the current file and its SHA.
2. **Write the original to `money-tracker-<timestamp>.enc.backup` locally** —
   before anything is uploaded, so a failure can never leave you with nothing.
3. Decrypt, detecting the iteration count. If it's already current, stop
   (`-f` re-encrypts anyway).
4. Re-encrypt, then decrypt *that* and compare it to the original plaintext.
   Nothing is uploaded that hasn't been proven readable.
5. Upload with the SHA from step 1, so a change made in the meantime is
   rejected rather than silently overwritten.

Do this while every device shows **Synced** — anything unsynced is lost when you
wipe them afterwards. Then on each device: Settings → Logout, or "Use different
account" on the login screen, and log in again. The wipe is required because the
stored credentials blob is still encrypted with the old parameters.

If you'd rather do it by hand, `-convert` works on a local file:

```sh
./money-decrypt -convert -out new.enc money-tracker.enc
```

## Format

Matches `src/lib/crypto.ts`:

```
salt(16) | nonce(12) | AES-256-GCM ciphertext+tag
key = PBKDF2-HMAC-SHA256(password, salt, iterations) -> 32 bytes
```

There's no header saying which iteration count made a given file. That's fine —
GCM authenticates, so the tool tries every count the app has ever shipped
(currently 600000, previously 100000) and reports which one opened it. A wrong
guess fails cleanly rather than producing garbage.

**The tool keeps reading old parameter sets after the app drops them.** That's
deliberate: `.enc` exports taken before a migration stay recoverable forever
without the app carrying the old code path. When the app's parameters change,
update `currentIterations` in `main.go` and leave the old value in
`knownIterations`.

`main_test.go` decrypts fixtures generated by the browser implementation — one
per parameter set — so the tests fail if the two ever drift apart. To regenerate
them, compile `src/lib/crypto.ts` and encrypt a known plaintext with it.

```sh
go test ./...
```
